# Protocol and persistence invariants

Stable identifiers for the guarantees Bsync is built to provide. Tests name the invariants they
check (`I02`, `T06`, …) in their display names, so `dotnet test --filter "DisplayName~I04"` selects them.

**Status** is one of:

- **Enforced (reference)**: implemented and tested with the in-memory store and in-memory authority.
  Durable providers must pass the same tests, including the public conformance suites in the `Bsync.Testing`
  package (`LocalStoreConformance`, `AuthorityConformance`), before they can claim it.
- **Partial**: some of the invariant is implemented; the gap is stated.
- **Open**: not implemented yet. The roadmap phase that owns it is given.

| ID | Invariant | Status | Where it is enforced / tested |
|---|---|---|---|
| I01 | Durable local acceptance: a successful local write and its pending intent survive supported crashes together. Memory-only stores advertise weaker durability. | Enforced (SQLite, process termination) | The write and its queue entry are one atomic store update. `SqliteLocalStore` commits each update in one `BEGIN IMMEDIATE` transaction (WAL, `synchronous=FULL` by default). Tests: `ProcessKillTests` (real child process killed mid-write, then `integrity_check`), `SqliteStoreTests.RestartKeepsState`. Power loss is not tested. `IndexedDbLocalStore`: one strict-durability transaction per update; offline edits survive a tab reload in Chromium, Firefox and WebKit (`IndexedDbBrowserTests.OfflineEditsSurviveReloadAndConverge`); unavailable storage is reported, not treated as success (`UnavailableStorageIsReported`). `InMemoryLocalStore` is explicitly not durable. A damaged SQLite file is rebuilt without losing readable local work, and the damaged file is kept (`RecoveryTests`, ADR-013). |
| I02 | Local edit preservation: acknowledging operation N never clears or overwrites a later edit. | Enforced (reference) | `SyncRecord.LocalRevision`, `PendingOperation.Revision`, `ILocalStore.UpdateAsync`. Tests: `S02`, `S02b`, `EditDuringConflictResolution`, `LocalWritesStayResponsiveDuringPush`, `StoreSnapshotsDoNotAlias`; across browser tabs sharing IndexedDB: `TabsDoNotAcknowledgeEachOthersEdits`, `ConcurrentTabsSerializeWrites`. |
| I03 | Atomic remote apply: page state and checkpoint commit together; never advance past unrepresented data. | Enforced (reference) | Pull page + checkpoint in one `UpdateAsync`; `SyncRecord.Observed` keeps server state skipped for dirty records. Tests: `S03`, `CrashDuringPageApplyIsAtomic`, `CheckpointCommittedWithPage`, `ReplayedAcknowledgementAdoptsNewerObservedVersion`, `LocalStoreConformanceTests.BatchIsAtomic`. UI observation boundary: Phase 6. |
| I04 | Retry-safe operations: retries reuse id and payload; duplicates replay the original result; reused id with a different request fails. | Enforced (reference) | Persisted `PendingOperation`; `InMemorySyncServer` receipts with request fingerprints. Tests: `S04`, the I04 cases of `AuthorityConformance` (duplicate replay, replayed conflict, reused operation id, purged receipt), `CrashBeforeSend`, `CrashBeforeLocalAcknowledgement`, `EngineTrafficRoundTripsThroughJson`. Bounded receipt retention (`PurgeReceipts`): a replay after its receipt expired is answered as a conflict and never applied twice (`SelectiveSyncTests.ReceiptExpiry`); the conflict handler then runs for a write that had succeeded, so receipts should outlive the longest offline period. Durable authority: Phase 4. |
| I05 | Atomic server concurrency check: base-version compare and write are one operation. | Enforced (reference, PostgreSQL) | In-memory authority under one lock; PostgreSQL: the feed row is locked (`SELECT … FOR UPDATE`) for the whole push transaction, so compare, write and receipt commit together. Tests: `AuthorityConformance` (in memory, over JSON, over HTTP, on PostgreSQL); `PostgreSqlAuthorityTests.ConcurrentInstancesKeepCommittedPrefix` (12 writers on two instances, every operation decided exactly once, last-writer-wins result), `OutageIsRetryable` (nothing half-committed). |
| I06 | Safe feed progress: a cursor covers a committed, gap-free prefix in an explicit epoch. | Enforced (reference, PostgreSQL) | In-memory authority: one commit sequence under one lock. PostgreSQL: per-feed serialized version allocation (ADR-005): a version becomes visible only after every lower version of its feed committed or rolled back. Checkpoints carry the epoch and a hash of collection, scope and scope fingerprint. Tests: the I06/I14 cases of `AuthorityConformance` (feed coverage, paging, resume, foreign checkpoint, new epoch); `PostgreSqlAuthorityTests.DelayedCommitIsNeverSkipped` (T27, T28 with a real uncommitted transaction), `ConcurrentInstancesKeepCommittedPrefix` (T30: a continuous reader sees versions in order; removing the lock fails it), `RestoreDrill` (new epoch and version floor after restoring tables). |
| I07 | Scoped isolation across tenant/principal/collection/filter/replica. | Enforced (reference) | Scope derived server-side from the authenticated principal (`SyncEndpointOptions.ResolveScope`), never from the body; `ScopedAuthority` gives each scope its own feed, versions and receipts; `CanRead` filters pages and hides documents in conflict and replayed outcomes; a `ScopeFingerprint` (permissions, filter) is bound into every checkpoint, so a changed scope cannot reuse an old checkpoint and gets `reset-required` with reason `scope-changed`. Tests: `HttpBindingTests.TenantIsolation`, `ConflictDoesNotLeak`, `AuthenticationRequired`; `SelectiveSyncTests.RevokeAndRegrant`, `PendingEditOnRevokedDocument`, `FilterChange`. Relational authority: Phase 4. |
| I08 | Bounded work: payloads, pages, retries and per-cycle work are bounded; exhaustion reports resumable remaining work. | Partial | `SyncOptions` budgets (validated), server `MaxOperationsPerPush`/`MaxPageSize`, `SyncResult.HasRemainingWork/Deferred`. Tests: `S01`, `S09`, `Batching`, `PageBudget`, `ConflictBudget`, `OversizedPushRefused`. Request body limit enforced while reading (`HttpBindingTests.Limits`); backoff with jitter and `Retry-After` (Phase 7); default-ordered collection queries read bounded pages from an index and stop at the limit (`DefaultOrderQueriesArePaged`, store conformance paging case). A custom query order still reads the whole collection. |
| I09 | Monotone reconciliation: no regression of confirmed versions or cursors; unknown/duplicate/omitted/contradictory outcomes never mark unsent data clean. | Enforced (reference) | `CorrelateOutcomes`, `ValidatePullPage`, `KnownVersion` guard. Tests: `UnknownOutcomeIsProtocolError`, `DuplicatedOutcomeIsProtocolError`, `MismatchedDocumentIsProtocolError`, `OmittedOutcomeIsDeferred`, `StaleResponseIsIgnored`, `OlderVersionIgnored`, `NonAdvancingPageRejected`, `DuplicateDocumentInPageRejected`; malformed wire messages refused (`WireFormatTests.InvalidFixturesAreRefused`). |
| I10 | Honest deletes and scope removals: tombstones propagate; eviction/revocation remove projections without global deletion; purge is distinguishable. | Enforced (reference) | Tombstones propagate (`TombstonesPropagate`). After an epoch reset, records absent from the snapshot are marked `MissingAfterReset` (hidden, kept, never propagated as deletions); after a `scope-changed` or `expired` reset they are removed from the device (`PurgedAfterReset`), never deleted on the server, and return unchanged when regranted. Records with local changes or a kept conflict are never purged. Tombstone purge on the authority raises a retention horizon: older checkpoints get `expired`, and an edit based on a purged version is rejected with `base-expired` instead of resurrecting the document. Browser eviction is detected by a new replica id (`DeletedDatabaseIsRepopulated`). Tests: `ResetTests`, `SelectiveSyncTests`, store conformance purge cases. |
| I11 | Deterministic conflict behaviour, no repeated side effects, preserved unresolved forks. | Enforced (reference) | Handler never re-runs for a replayed outcome (`S04`); LWW is upload-order independent (`S10`); handler contract documented as pure. Default policy keeps the local change durably as an unresolved conflict (`SyncRecord.Conflict`) with list/resolve/discard in the engine and `ISyncCollection` (`ConflictResolutionTests`, `ConflictsThroughCollection`, and in the notes PWA across two browser devices: `ConflictIsShownAndResolved`), across restarts on SQLite (`ConflictSurvivesRestart`) and through purges (`RevokedConflictIsKept`). Field-level three-way merge with stated semantics (`ThreeWayMergeTests`). Members declared sets or counters merge semantically (`ThreeWayMergeOptions`; `ThreeWayMergeTests.SetsMerge`, `CountersMerge`). |
| I12 | Identity/clock integrity: bounded, validated HLC; defined overflow and restart; origin time separate from version/cursor; database ordering matches comparison. | Enforced (reference) | `HlcTimestamp` validation and strict parser, bounded counter with carry, high-water seeding, server skew bound. Tests: `S05`–`S08`, `ClockValidationTests`, the I12 case of `AuthorityConformance` (origin timestamps, clock-skew bound); strict wire encoding (`docs/protocol/v1.md` §2.3–2.4). Replica identity/incarnation for clones: Phase 3. |
| I13 | Repair after notification loss. | Enforced (reference, browser) | Hints never carry data: server-connected circuits re-read on commit hints; local sessions sync on SSE hints (`LiveHints`), browser `online`/visibility events, local writes and an interval. Tests: `BlazorIntegrationTests.HintTriggersSync`, `LostHintsStillConverge` (every hint dropped), `HintReconnects`; `HintStreamTests` (announce on connect and commit, scoped, not supported, unauthenticated); browser `HintsReachWebAssembly`, `OnlineEventUploadsImmediately`. |
| I14 | Safe recovery/reset preserving pending edits. | Enforced (reference, SQLite) | Generation-based resnapshot (`docs/protocol/v1.md` §6.1) with a reset reason (`epoch`, `scope-changed`, `expired`): pending edits, operations and kept conflicts are kept and resent, versions not compared across generations, unseen clean records hidden or purged by reason, crash-safe sweep; authority version floor after restore. Tests: `ResetTests`, `SelectiveSyncTests`, `RandomSchedulesWithRestoresConverge` (60 seeded schedules, four policies, with 12–26 restores each), `SqliteStoreTests.EnginesOnSqliteConverge`. Damaged SQLite replicas are rebuilt into a new generation with a resnapshot (`RecoveryTests.RebuildKeepsLocalWork`). |
| I15 | Cancellation and lifecycle: no partial logical writes; post-commit cancellation is an unknown outcome. | Partial | `CancelledWriteCommitsNothing`, `CancellationAfterServerCommit`, `CancelledUpdateCommitsNothing` (all stores); observer subscriptions are disposable and a throwing observer cannot affect replication (`ObservationTests`); the session owns its loop, hint listener, lease and lifecycle attachment and stops them on account switch or disposal (`StopEndsLoop`, `AccountSwitch`, `LifecycleAttachment`); `Pause`/`Resume` for native suspend. |
| I16 | Truthful confirmation: local commit vs pending vs accepted vs rejected vs observed. | Partial | `LocalWriteReceipt` (local commit only), `SyncRecord.IsDirty/Pending/Rejection/MissingAfterReset`, `SyncResult.IsComplete/ResetPerformed`, post-commit change observation (`SyncEngine.Observe`); collection-level `SyncStatus` (pending count updated at each local write) and per-item `SyncItemStatus` (`Pending`, `Rejected`, `MissingAfterReset`); `SyncWriteResult` distinguishes `SavedLocally` from `AcceptedByServer`. A server watermark ("current up to") is not exposed yet. |
| I17 | Schema compatibility; old clients cannot erase unknown fields. | Partial | Documents that declare `[JsonExtensionData]` preserve unknown members through edit, push and three-way merge (`WireFormatTests.UnknownFieldsSurviveEdit`, `ThreeWayMergeTests.UnknownFieldsMerge`); receivers ignore unknown envelope members. Local store schemas are versioned and migrate forward in place, keeping pending work (SQLite 1→2: `SqliteMigrationKeepsPendingWork`; IndexedDB 1→2 in three browser engines: `SchemaOneUpgradeKeepsPendingWork`); newer schemas are refused (`NewerSchemaRefused`, `UpgradeFromAnotherTab`). Not enforced for documents without an extension-data bag. Rolling domain-schema upgrade: an app left behind gets `upgrade-required`, keeps its work and uploads it once after updating (`SchemaUpgradeTests.RollingUpgrade`). Documents upgrade themselves on read with `IJsonOnDeserialized` + `DocumentUpgrade.TryTake`, in local stores and on the wire (`DocumentUpgradeTests`); an upload in flight across a shape change is answered `operation-id-reused` (ADR-013). |
| I18 | Host equivalence of authorization and business rules. | Enforced (reference) | HTTP endpoints, `InProcessTransport` and `ServerSyncCollection` (Interactive Server, prerendering, static SSR) all call the same `ISyncAuthority` with a `SyncCallContext` built from authenticated state; `HttpBindingTests.HostEquivalence`, `BlazorIntegrationTests.ServerRecipe`, `WebAppSampleTests`. |
| I19 | Fair progress: rejected or repeatedly conflicting records do not block independent work. | Enforced (reference, PostgreSQL) | Rejected records are parked; per-document conflict budget; per-run exclusion; kept conflicts leave the push queue. Tests: `MixedOutcomes`, `RejectedRecordDoesNotStarveQueue`, `ConflictBudget`, `ResolveAndUnrelatedProgress`. Parked rejections are listed and can be retried as new operations or reverted (`RecoveryTests.RetryRejected`, `Revert`). Dependency groups (protocol §4.1) are applied all-or-nothing by both authorities and never block unrelated work: a failing member parks only its own group (`GroupTests`, `PostgreSqlAuthorityTests.GroupsAreAtomic`, `SaveAllIsAtomic`). |
| I20 | Eventual convergence under stated assumptions after quiescence. | Partial | `RandomizedConvergenceTests` (60 seeded schedules, each also with restores: client-wins, server-wins, LWW and the default defer policy, random batch sizes, lost responses, crashes before acknowledgement, edits during flight; with defer, kept conflicts are resolved or discarded during the schedule and at quiescence) with a reference model: LWW ends on the greatest authoring timestamp; server-wins, LWW and defer never invent timestamps (a mutation inverting LWW fails all 15 LWW seeds). Assumptions: one available authority, a single collection without scopes, no schema change, unbounded receipt retention, conflict handlers that terminate, and every kept conflict eventually decided. The schedules also write dependency groups; changes parked with their group are retried at quiescence. |

## Assumptions behind I20 today

The randomized suite covers the in-memory authority and store, a single collection, whole-document
last-writer or policy-based resolution, server restores, and a finite schedule followed by reliable
connectivity; SQLite replicas are covered by one seeded run. Revocation, filter changes, receipt expiry and
tombstone purge are covered by targeted tests, not by the randomized suite. Not covered: schema changes, and
clocks more than the server's skew bound ahead. With the default `Defer` policy convergence additionally
requires every kept conflict to be resolved or discarded. Passing a finite randomized suite is evidence, not
proof.
